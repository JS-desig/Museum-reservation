# 菏泽市科技博物馆预约与门禁系统 — 上线前冒烟检查清单

> 版本: v1.1 | 对应需求: 7.3 上线保障 | 检查项: 11 项核心链路
> 目标: 版本发布后核心流程(预约 → 核销 → 通行 → 统计)**零逃逸**

## 一、执行时机

| 场景 | 是否执行 | 说明 |
|---|---|---|
| 生产环境版本发布前 | ✅ 必须 | 阻断发布的质量门禁 |
| 需求变更/热修复后 | ✅ 必须 | 涉及预约、核销、统计链路的改动 |
| 闸机固件升级后 | ✅ 必须 | 重点验证第 8~10 项 |
| 数据库脚本变更后 | ✅ 必须 | 追加执行 `tests/sql_consistency.py` |
| 日常回归 | 由 `pytest` 用例集覆盖 | 冒烟只验主链路，不做分支穷举 |

## 二、前置条件

1. 目标环境后端已启动，`GET /api/health` 返回 `{"status":"UP"}`。
2. 数据库已执行 `sql/schema.sql` 且完成种子数据初始化。
3. **基础数据在位**：至少 1 个启用时段、1 条已发布公告、1 条上架展品、场馆状态为「开放」。
4. 准备**专用冒烟账号**（脚本按批次号自动生成，不复用真实游客证件）。
5. 执行窗口避开客流高峰，脚本会写入真实数据（见第六节）。

## 三、检查清单

| # | 检查项 | 操作 | 预期结果 | 关联需求 |
|---|---|---|---|---|
| 1 | 服务健康检查 | `GET /api/health` | `status=UP` | 五.可靠性 |
| 2 | 场馆信息 | `GET /api/venue` | 返回名称/开放时间/须知，非空 | 3.1 场馆信息 |
| 3 | 公告列表 | `GET /api/announcements` | 仅返回已发布，按发布时间倒序 | 3.1 公告 |
| 4 | 展品列表 | `GET /api/exhibits` | 仅返回上架展品，字段完整 | 3.1 展厅展品 |
| 5 | 登录 + 实名绑定 | `POST /wx/login` → `POST /wx/realname` | `is_verified=true`，证件号脱敏 | 3.1 用户认证 |
| 6 | 选日期时段 | `GET /wx/slots?visit_date=今日` | 时段可查，`余量 ≤ 容量`，非闭馆 | 3.1 预约 |
| 7 | 创建预约 | `POST /wx/reservations` | 返回 12 位预约码，状态 `booked` | 3.1 预约 |
| 8 | 闸机核销入馆 | `POST /gate/check` (direction=in) | `result=success`，**绿屏开闸** | 3.3 验票核销 |
| 9 | 重复核销拦截 | 同一预约码换 `device_seq` 再核销 | `result=fail`，**红灯拒绝** | 3.3 异常处理 |
| 10 | 出馆核销 | `POST /gate/check` (direction=out) | `result=success`，在馆人数回落 | 3.3 / 四.一致性 |
| 11 | 数据对账 | `GET /admin/stats/dashboard` | `在馆人数 = 今日入馆 - 今日出馆`；本次核销记录后台可见 | 四.数据一致性 |

## 四、自动化执行

```bash
cd backend
python tests/smoke_test.py                                  # 默认 http://127.0.0.1:8000/api
python tests/smoke_test.py --base-url http://<生产域名>/api   # 指定目标环境
```

- **退出码**：`0` = 全部通过（允许发布）；`1` = 存在失败项（**阻断发布**）。
- 服务不可达时预检 2 秒内中止，不逐项重试拖长耗时。
- 输出每项 `[PASS]/[FAIL]` + 耗时 + 失败原因，末尾给出结论，可直接贴入发布单。

配套数据层对账（需库访问权限）：

```bash
python tests/sql_consistency.py    # 7 项硬校验, 退出码 0/1
```

## 五、失败处置

| 失败项 | 常见原因 | 处置 |
|---|---|---|
| 1 服务健康 | 服务未起 / 端口占用 / DB 连接失败 | 查看服务日志，确认 DB 可达后重试 |
| 2~4 基础数据 | 种子数据缺失、公告被全部下架 | 补录基础数据，勿带病发布 |
| 5~7 预约链路 | 实名接口异常、时段已满、场馆被置闭馆 | 检查时段容量与场馆状态 |
| 8~10 闸机链路 | 契约/校验逻辑被改动、闸机离线 | 重点排查 `_validate` 分支与设备心跳 |
| 11 对账 | 事务未同提交、统计口径被改 | 立即执行 SQL 对账定位，**禁止放行** |

**回滚判据**：任一项失败且 30 分钟内无法定位修复 → 回滚至上一稳定版本，保留现场数据供复盘。

## 六、注意事项

- 冒烟脚本会**写入真实数据**：1 笔预约、3 条核销记录、2 条通行日志（入/出各一）。建议在生产使用专用批次号（输出中的 `批次`）识别，发布后按 `device_seq` 前缀清理。
- 第 9 项依赖第 8 项成功，第 10 项依赖第 8 项成功；前置失败时后续项标记跳过而非误报通过。
- 本清单由 `backend/tests/smoke_test.py` 脚本化，与 `docs/测试用例设计文档.md` 第五节的「上线冒烟清单（11项核心链路）」一一对应，并已接入 CI 流水线。
